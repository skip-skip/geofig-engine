# Phase 15: Declarative API + provider refactor (interoperability M1)

**Status**: complete
**Phase**: 15
**Version target**: v0.2.0
**Dependencies**: none (phase overview)

## Description

Phase 15 delivers **geofig-engine M1 — Declarative API + interoperability**, the
next major development focus defined in `ARCHITECTURE.md`
(`## Implementation Roadmap` → M1) and `../PIPELINE_MODULES.md`
(`## Implementation Order` → M1, item 1). It converts the engine from the
`Dataset`-based legacy surface to a single declarative, provider-driven entry
point while keeping the legacy path intact and deprecated.

This epic file lists the phase-level intent. Each `15_wpN` ticket is a single
commit item that implements one piece; tickets are created in
`tasks/open/`.

### Phase goals (M1)

1. **Data** — one input abstraction: `DataProvider` Protocol
   (`columns` / `resolve` / `expand` / `subset` / `unique_values` /
   `dimensions`), accepted duck-typed. `DataFrameProvider` wraps raw frames
   (standalone use); `DatasetProvider` adapts the legacy `Dataset`. No
   geodata/geochemmodel import anywhere in `geofig_engine`.
2. **Spec** — an exported `TEMPLATES` registry (`register_template` /
   `get_template`) resolving template keys and the keys emitted by
   `geochemmodel.VisualizationEncoding`; a duck-typed template recipe
   (`layers`, `coord`, `default_settings`, `name`) with `FigureTemplate`
   adapted to the same shape.
3. **Render** — canonical `render_template(data, template=<key>|FigureTemplate,
   mapping=, settings=, iterators=, facet=, coord=, savedir=) -> list[Figure]`,
   all args after `data`/`template` optional; raw `DataFrame` accepted and
   wrapped. Provider-driven `FigureGenerator`; legacy `FigureEngine` untouched.
4. **Audit / compat** — legacy entry preserved as `render_template_legacy`
   (call-time `DeprecationWarning`); `Dataset` & co. re-exported through a
   `deprecated.py` module with **import-time** warnings; public vs deprecated
   `__all__` split. Per versioning policy these deprecations are introduced in
   a MINOR (v0.2.0) and removed no earlier than 1.0.0.

### Registry templates (added this phase)

`bivariate`, `boxplot_with_points`, `dendrogram`, `site_map`,
`particle_overlay`, plus thin adapters re-registering the legacy factory set
(`histogram`, `pie`, `radar`, `timeseries`, `isotope`, `npr_nnp`, `anp_agp`,
`nagph_nag`, `piper`, `stiff`).

### Geo support (added this phase)

`CoordGeo`, geo geoms (site point, boundary, label, annotation-inset, image),
geometry/image renderer handlers, and the `[geo]` extra. **Deferred to M2:**
tile basemaps, DEM contour, stream geoms.

### Versioning notes (must hold)

- Public surface governed by `## Versioning` in `ARCHITECTURE.md`; commits
  label the target (`geofig-engine: <scope> → v0.2.0`).
- Deprecation warnings introduced here are a **MINOR** change; shims removed
  only in a MAJOR (no earlier than 1.0.0).
- Registry/template keys are public API: additions in MINOR, removals only in
  MAJOR.

## Phase-level acceptance criteria

- [ ] `geofig_engine.render_template` returns `list[Figure]`; all optional args
      after `data`/`template`; raw `DataFrame` accepted (standalone usage)
- [ ] `TEMPLATES` / `register_template` / `get_template` exported; pipeline +
      legacy keys resolvable; unknown keys raise a helpful error
- [ ] Legacy entry returns `(specs, figures, legend_fig)` via
      `render_template_legacy` with a call-time warning; `Dataset` & co. warn at
      import time; legacy test suite stays green (1039 + new, no skips from
      warning policy)
- [ ] `geochemmodel.ModelResult.render()` lazy path works against the new API
- [ ] `geofig_engine` imports neither `geodata` nor `geochemmodel`
- [ ] Geo geoms + `CoordGeo` render; `[geo]` extra declared; tiles/contour/
      streams explicitly deferred in docs
- [ ] ROADMAP renumbered sequentially per `15_wp12`; phase marked ✅ at review
- [ ] Version bumped `0.1.0 → 0.2.0`, tagged `geofig-engine-v0.2.0`,
