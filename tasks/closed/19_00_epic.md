# Phase 19: Dashboard serialization and incremental updates

**Status**: complete
**Phase**: 19
**Version target**: v0.5.0 (MINOR — additive; no removals before 1.0.0)
**Dependencies**: none (phase overview / review ticket)

## Description

Add a backend serialization path suitable for a web dashboard that needs
higher-frequency template and data updates. Today the round-trip serializer
(`spec_to_json` / `spec_from_json`) can persist a `FigureSpec`, but the canonical
`render_template` entry builds specs **and** renders Matplotlib figures in one
call, so there is no public spec-only or JSON-only template API. The current
serializer is also a one-spec Python round-trip format, not a versioned wire
contract with stable figure identities, template/data separation, legend data,
or update patches.

This phase keeps the existing round-trip format and Matplotlib path unchanged.
It adds:

1. a spec-only template build API;
2. a versioned, browser-safe dashboard wire format for full snapshots;
3. a transport-agnostic patch format for higher-frequency updates;
4. contract tests and documentation.

The frontend renderer, WebSocket/SSE transport, and Matplotlib ingestion of the
dashboard schema are **out of scope**. `MatplotlibRenderer` continues to consume
`FigureSpec` objects through the existing path.

## Decisions locked (with the requester)

- **Existing serializer stays intact.** `figure_spec_to_dict`, `spec_to_json`,
  and their `*_from_*` counterparts keep their current round-trip semantics.
- **Add, do not replace.** The dashboard format is a separate projection from
  `FigureSpec`; it does not become the canonical Python persistence format.
- **Spec-only entry point.** `build_template_specs(...)` becomes the shared
  template → `FigureSpec` path; `render_template(...)` calls it before rendering.
- **Full snapshot plus patches.** A versioned snapshot payload supports initial
  display/recovery; a patch protocol supports higher-frequency updates.
- **Template/data split.** Low-frequency structure (layers, geom, coord, facet,
  settings, layout, legend) is separated from high-frequency columnar data.
- **Stable identity.** Every figure/layer gets deterministic IDs; a canonical
  `template_hash` identifies structural definitions; payloads and patches carry
  monotonically increasing `revision` values.
- **Browser-safe JSON.** `NaN` / `NaT` / `Infinity` normalize to `null` by
  default; datetimes become ISO strings; numpy scalars become Python scalars;
  callables are rejected with a clear error.
- **No new required dependency**, no upstream imports (`geodata` /
  `geochemmodel`), and no `MatplotlibRenderer` changes.
- **No dashboard → spec decoder in v0.5.0.** Matplotlib remains on the
  `FigureSpec` path; a decoder can be a later phase if one wire format is wanted.

- [x] `build_template_specs(...)` builds specs for all ten seeded template keys
      without rendering, including `SpecRecipe` keys (`piper` / `stiff`)
- [x] `render_template(...)` output and saved PNGs remain unchanged
- [x] Dashboard snapshots are versioned, deterministic, browser-safe JSON and
      split template definitions from columnar data

      `revision`, and a serialized legend payload

      remove a figure; applying a patch reproduces the fresh full snapshot

      clear errors

      and green

      behavior change
